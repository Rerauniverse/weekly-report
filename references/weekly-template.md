# 工作周报模板与规范

本文件为 `weekly-report` skill 的配套参考。生成周报时务必读取并遵循以下模板与规则。

归类维度与润色规则**继承自 `daily-report` 技能**（已复制至此，保证周报 skill 自包含、不依赖 daily-report 已安装），聚合与去重规则为本 skill 独有。

---

## 一、周报标准模板（Markdown）

```
# 工作周报 — {YYYY-MM-DD} ~ {YYYY-MM-DD}（第 N 周）

## 一、本周概览
{2–3 句话总览本周整体节奏与重心}。{一句话结论：如"本周重心在多租户方案落地，整体按计划推进"。}

## 二、关键进展
### {主题/项目 A}
- {动词开头的具体事项 + 量化结果}（周一→周三→周五时间线：{简述各日推进}）
### {主题/项目 B}
- {…}

## 三、量化成果汇总
- {指标 1}：{本周最新值 / 累计增量}（如 接口响应 800ms→200ms）
- {指标 2}：{…}（如 合入 PR +12）

## 四、风险与阻塞
- {风险/阻塞}：影响 {什么}，状态 {仍 open / 已解决（周X 解决）/ 待跟进}，需要 {谁/资源} 支持

## 五、下周重点计划
- {高/中/低} {事项}
- {高/中/低} {事项}

---
*提交人：{name}　|　{部门/项目}　|　周期：{YYYY-MM-DD} ~ {YYYY-MM-DD}*
```

说明：
- "本周概览"是门面，先给结论再给支撑，别堆流水账。
- "关键进展"是核心，必须按主题/项目**跨日聚合**，同一事项的多次记录合并成一条并保留时间线。
- "量化成果汇总"把散落在一周各天的数字集中呈现，便于向上汇报。
- "风险与阻塞"跨日去重后标注状态，避免同一风险重复啰嗦。
- "下周重点计划"是日报"明日计划"的周级升级，去重、收敛到 3–8 条。

---

## 二、归类规则（继承自 daily-report）

| 分类 | 涵盖内容 |
|------|----------|
| 开发/技术 | 写代码、修 bug、部署上线、技术方案、code review、测试用例 |
| 协作沟通 | 跨团队对齐、需求评审、回复邮件/群消息、客户沟通、答疑 |
| 会议 | 站会、评审会、周会、一对一、复盘会 |
| 学习成长 | 看文档、培训、技术调研、复盘总结、读源码 |
| 其他 | 行政、招聘、规划、周报月报等不便归类的事项 |

归类准则：
- 一个事项只进最贴切的一类，可加小标号（如"开发：修复登录越权漏洞"）。
- 同一类下多条时按重要性排序。
- 纯会议若无实质产出，可并入"会议"并一句话说明结论。

## 三、润色规则（继承自 daily-report）

1. **动词开头**：完成 / 推进 / 修复 / 评审 / 对齐 / 上线 / 排查 / 输出。
2. **省略主语**：直接写动作与对象，去掉"我/我们"。
3. **结果导向**：写"做完什么、达到什么效果"，少写"做了什么努力"。
4. **量化优先**：时间、数量、百分比、金额优先于模糊描述。
5. **去口语**：删掉"大概、好像、弄了一下、搞了、看了下"等词。
6. **风险明确**：风险与阻塞要写"影响 + 需要的支持"。

---

## 四、聚合与去重规则（本 skill 独有，分支 5 = A）

### 4.1 归并识别

- **硬归并（优先）**：若日报条目带有统一标签前缀（如 `[Zeekr签到]`、`【项目A】`、`(多租户)`），同一标签跨日的所有条目合并为一条"关键进展"。合并后保留"周一→…→周日"的进展时间线，标注累计进度（如"方案设计 30% → 80%"）。
- **软归并（兜底）**：无标签时，按"主题关键词 + 语义相似"归并。例如多天都出现"多租户方案 / 多租户设计 / 多租户评审"相关条目，归并为一条"多租户支持"进展。
- 归并时**不丢失信息**：把各日的增量与时间点都串起来，而非只保留最后一天。

### 4.2 量化汇总

- 同一指标多次记录 → 取**最新值 + 累计增量**。例：`接口响应 800ms → 200ms`；`合入 PR 本周 +12`。
- 可累加量（完成数、合入数、处理客诉数等）直接求和并标注。
- 不可直接相加的指标（如"响应时间"）表述为"起点 → 终点"。

### 4.3 风险与阻塞状态判定

- 某风险在周中某天出现，后续天数**不再出现** → 标 `已解决（周X 解决）`。
- 持续多天出现 → 标 `仍 open`，并标注持续天数（如"持续 3 天"）。
- 仅出现一次、周末仍无结论 → 标 `待跟进`，注明出现日期。
- 跨日去重：同一风险只在周报里出现一次，状态栏汇总整周表现。

### 4.4 下周重点计划生成

- 汇总一周各天日报"明日计划"中**未关闭、跨日延续**的事项。
- 叠加本周新提出的方向/目标。
- 去重、收敛为 3–8 条周级重点，每条带优先级（高/中/低），写明具体交付物（避免"继续跟进"这类不可验收表述）。

## 五、示例

### 示例 A：研发（输入为 3 天日报片段）

**原始输入（节选 3 天日报）：**
> 周一：开发：修复登录态 Token 未失效缺陷，已合入主干。协作：与前端对齐鉴权接口字段。
> 周三：开发：推进多租户方案设计（约 30%）。会议：多租户需求评审通过。
> 周五：开发：完成多租户数据隔离骨架，进度 80%。风险：多租户压测环境未就绪。

**成稿（周报节选）：**
```
## 二、关键进展
### 登录与鉴权
- 修复登录态 Token 未失效缺陷并合入主干（周一）；与前端对齐鉴权接口字段、统一 err_code（周一）。

### 多租户支持
- 推进多租户方案：需求评审通过（周三）→ 完成数据隔离骨架（周五，进度 80%）。

## 四、风险与阻塞
- 多租户压测环境未就绪：影响性能验证，状态 仍 open，需运维本周内交付压测集群。

## 五、下周重点计划
- 高 完成多租户数据隔离剩余 20%，启动联调。
- 中 推动压测环境就绪，开展多租户性能验证。
```

### 示例 B：产品 / 项目

**原始输入（节选）：**
> 周一：产品：与需求方确认新版首页范围，锁定 3 个首发模块。
> 周三：产品：完成新版首页 PRD 初稿 v0.1。风险：支付回调延迟已造成重复下单投诉。
> 周五：协作：支付回调延迟问题研发已定位，进入修复。

**成稿（周报节选）：**
```
## 二、关键进展
### 新版首页改版
- 确认范围锁定 3 个首发模块（周一）→ 完成 PRD 初稿 v0.1（周三）。

## 三、量化成果汇总
- 需求确认：锁定首发模块 3 个。
- PRD：产出 v0.1 初稿 1 份。

## 四、风险与阻塞
- 支付回调延迟：曾造成重复下单投诉（周三）；研发已定位并进入修复（周五），状态 已解决。
```

## 六、常见坑（继承自 daily-report + 周报补充）

- 不要把"开会"写成产出且无结论——会议要带结论或行动项。
- 不要堆砌形容词（"高效地""顺利地"），用事实和数据说话。
- 明日计划不要写"继续跟进"这种无法验收的话，写明具体交付物。
- 用户没提日期/姓名时，用 `{YYYY-MM-DD}` 占位并询问，不要硬编。
- **周报特有坑**：不要机械拼接 5 天日报——必须跨日聚合去重，否则周报比日报还啰嗦。
- **周报特有坑**：风险状态不能简单堆砌，要基于"是否跨日再现"给出 open / 已解决判断。
